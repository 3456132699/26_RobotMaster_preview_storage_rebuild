# 机器人制造流程 · 从需求到上场

> 给白星 · 2026-11-05
> 起因：你想理清「需求 → 硬件 → 代码 → 板子 → 装车」这条链。**方向对，但这条链不是串行的**——
> 真正的流程是「三条线并行 + 一个枢纽 + 两次收口」。下面逐段拆。

---

## 0. 先说结论

| 你的理解 | 评价 | 问题在哪 |
|---|---|---|
| ① 一起确定功能需求 | ✅ 对，但少了一步 | 功能需求必须**翻译成可验证的工程指标**，否则后面没法设计 |
| ② 机械组和算法组确定所需硬件设备 | ⚠️ 半对 | **「硬件」要看指什么**：机械零件归机械；电机/驱动器/传感器/算力平台必须**电控一起定** |
| ③ 交给电控软件组确定代码实现 | ⚠️ 顺序反了 | 软件不是"接需求后开始"，而是**和机械并行**，先用开发板跑通逻辑 |
| ④ 电硬根据所有要求设计板子 | ❌ **这是最关键的偏差** | 电硬**不是最后接单的**。电硬要全程在场——「接口」要早，「PCB」可以晚 |
| ⑤ 再和机械沟通板子装车 | ✅ 对，但太晚 | 装车是**最后一次集成**，不是第一次沟通。而且少了**联调**和**检录预演** |

**一句话总结你的偏差**：你把流程想成了一条**接力赛**（一棒交一棒），
但机器人是**并行工程**——四条线同时跑，靠**接口定义**在中间对齐，最后两次收口（集成、验证）。

---

## 1. 「硬件设备」这个词要先拆开

第 ② 步容易出问题，就是因为「硬件」在机器人里指两件完全不同的事：

| 类型 | 谁定 | 例子 |
|---|---|---|
| **机械硬件** | 机械组 | 铝型材、3D 打印件、轴承、同步带、丝杆、舵机支架 |
| **电气硬件** | **机械 + 电控共同定** | 电机、驱动器、传感器、相机、算力平台、电池、接插件 |

**为什么电机不能只由机械定？**

机械给的是**负载**（要多大扭矩、要多快、行程多少），但选电机还要看：

- 转速 / 减速比 → 决定控制方式（开环？编码器闭环？）
- 堵转电流、额定电流 → 决定**驱动器选型和电源预算**
- 电压等级 → 决定接 16.8 V 直驱还是降压
- 有无编码器 → 决定软件要不要做 PID

所以**电机选型是机械和电控的联合动作**：机械提需求 → 电控算电流和电压 → 一起定型号。

## 2. 正确流程：五阶段 + 四条并行线

### 阶段 0 · 需求 → 指标（最容易被跳过，也最致命）

「我要能夹起方块」是**功能需求**，机械拿到这个没法设计。必须翻译成**工程指标**：

| 功能需求 | 工程指标（可验证） |
|---|---|
| 能夹起方块 | 夹持力 ≥ ? N（方块 EVA 60 g，加安全系数） |
| 能放到兑换孔里 | 重复定位精度 ±? mm（孔 Ø80 mm，留余量） |
| 7 分钟内拿够分 | 单次循环时间 ≤ ? s，往返次数 ≥ ? 次 |
| 能爬台阶 | 爬坡角 ≥ 30°，越障高度 ≥ 200 mm |
| 整车不超重 | 拾取车总质量 ≤ 15 kg（制作规范硬约束） |

> 📌 **这一步的产出是《需求-指标对照表》**。没有它，后面所有争论都是「我觉得」对「我觉得」。
> 大一队伍最常犯的错就是从「我们要做个夹爪」直接跳到「画夹爪」，中间的指标全凭感觉。

### 阶段 1 · 方案设计（四条线并行，不是串行）

| 线 | 在做什么 | 输出 |
|---|---|---|
| **机械** | 构型选型 → 传动方案 → 力矩核算 → 尺寸链 | 机构方案图、负载曲线、**安装接口 + 质量预算** |
| **视觉 / 算法** | 识别目标是什么 → 需要什么视野/帧率 → 算力需求 | 相机型号、分辨率、**算力平台型号 + 功耗** |
| **电控软件** | 控制频率、闭环需求、状态机、通信协议 | **控制架构、通信协议草案、电机控制方式** |
| **电控硬件** | 汇总上面三家的电气需求 → 电源预算 | **《电源预算表》《电气接口清单》** |

**枢纽是「接口定义」（ICD, Interface Control Document）**——这是整个流程里最关键、也最容易被忽略的一份东西。它回答：

- 谁跟谁通信？用什么协议？速率多少？
- 谁给谁供电？几伏几安？
- **地怎么共**？（共地是所有疑难杂症的源头）
- 机械和电气的**机械接口**：板子多大、几个安装孔、孔距多少、线从哪出

> 🔴 大一队伍最常见的崩盘就在这里：**各做各的，联调时发现通信协议不一致、板子装不进机构、电源带不动**。
> 不是能力问题，是**没人负责把接口写下来**。

### 阶段 2 · 方案冻结（必须有一次，否则永远改不完）

明确宣布：「XX 月 XX 日之后，接口、尺寸、电源规格、通信协议**不再改**，除非走变更流程。」

冻结清单：

- [ ] 机械外廓尺寸 + 安装孔位
- [ ] 电机/驱动器型号（含数量）
- [ ] 电源规格（输入电压、各路输出、总功率、余量）
- [ ] 通信协议版本
- [ ] 板子尺寸与安装方式
- [ ] **合规检查**：尺寸 ≤350×350×400、重量 ≤15 kg、电压 ≤16.8 V（此时不查，后面返工代价更大）

> 💡 冻结不是"不许改"，是"改了要通知所有人"。**没有冻结节点 = 所有人都在移动靶上工作。**

### 阶段 3 · 分头实现（并行，但有先后依赖）

| 线 | 顺序 | 关键点 |
|---|---|---|
| **机械** | 3D 建模 → 加工/打印 → 装配 → 干涉检查 | 装配前先做**虚拟装配**，别等实物撞了才发现 |
| **电控硬件** | 原理图 → **单板验证** → PCB → 打样 → 焊接 → 上电验证 | **先面包板验证电路，再画板**。跳过这一步必翻车 |
| **电控软件** | **开发板上先跑通** → 再移植到自制板 | 不要等板子做出来才写代码 |
| **视觉** | 数据集 → 算法 → 开发板上跑 → 现场调参 | 尽早用真实场地/道具测试 |

> 📌 **关键认知**：电硬的「接口定义」要在阶段 1，「PCB 出图」可以在阶段 3。
> 这两件事解耦了，电硬就不会成为瓶颈——**你不需要在机械还没定的时候就把板子画完**。

### 阶段 4 · 集成与联调（最耗时间，最容易被低估）

顺序必须是：**单板 → 分系统 → 整车**，不能跳。

1. **单板验证**：板子单独上电，量各路电压、烧个点灯程序、通信自测
2. **分系统联调**：底盘单独跑、机构单独动、发射架单独打
3. **整车联调**：所有系统一起跑，看干扰、看复位、看时序
4. **场地实测**：真实场地跑一遍，看时间够不够

**联调常见崩溃点**（按发生概率排）：

| 现象 | 根因 |
|---|---|
| 电机一转就复位 | 电源没分路、电容不够、地没处理好 |
| 通信丢包 | 没共地、线太长、电机干扰、波特率不匹配 |
| 机构动了但板子报错 | 电机反电动势灌回、缺少续流/隔离 |
| 一切正常但装不进去 | 机械接口没冻结，或板子尺寸后改 |

### 阶段 5 · 验证与上场

- **检录预演**：按规则 5.7-e 走一遍——展示 Sch/Pcb 文件 → 演示基本功能 → 演示保护动作（失控断电、堵转断电、急停）
- **合规自查**：尺寸/重量/电压/丝印（队名+绘制者+时间）/线束固定不裸露
- **7 分钟全流程演练**：完整跑一遍，掐表看哪一步超时
- **备件清单**：备用板、备用线、备用保险丝、备用程序 U 盘

## 3. 电硬到底什么时候介入（你的核心关切）

### 3.1 一张泳道图看清"全程在场"

> 上面内联的那张泳道图就是这张。看**电控硬件那一行**：从第 1 阶段就在场，不是最后一格才出现。

### 3.2 电硬在五个阶段的具体动作

| 阶段 | 你该做什么 | 产出物 |
|---|---|---|
| **需求→指标** | 给出**电气侧约束**：电压上限 16.8 V、重量预算里给电气留多少、板子可用空间 | 电气约束清单（一页纸） |
| **方案设计** | 汇总所有用电设备 → 算**电源预算** → 定**接口清单** | 《电源预算表》《电气接口清单》 |
| **方案冻结** | 锁定：电池规格、各路电压电流、板子尺寸与孔位、通信接口、接插件型号 | 冻结版 ICD |
| **分头实现** | 原理图 → 面包板验证 → PCB → 打样 → 焊接 → **单板验证** | 可工作的主控板 |
| **联调** | 装车、布线、排故、抗干扰 | 整车电气系统 |
| **验证** | 检录演示、保护动作演示、备件 | 通过检录 |

### 3.3 如果电硬最后才进场，会发生什么

- 板子画完了，发现机械留的空间只有 60×40 mm → **重画**
- 电源按 5 路设计的，实际要 8 路（多了一个云台） → **重画**
- 机械把电机装在板子正上方，线没法出 → **改结构，等件**
- 软件要 CAN，板子只留了 UART → **加飞线，可靠性崩**

> 这四条每一条都意味着**至少一轮打样周期**。而打样是最不能压缩的时间。

## 5. 你们这支队伍的现实约束

| 约束 | 对流程的影响 |
|---|---|
| **7 分钟比赛** | 阶段 5 必须做**全流程计时演练**；机构动作时间要反推进指标（阶段 0） |
| **检录一票否决** | 尺寸/重量/电压/丝印/线束是**设计约束**，不是最后检查项。阶段 2 冻结时就要查 |
| **硬件加分 100 分** | 板子要"能被认定"：丝印齐、Sch/Pcb 齐、**真装在上场设备上**。所以电硬的产出必须真的上车，不能做"演示板" |
| **大一队伍，人手有限** | 流程可以简化，但**两件事不能省：需求→指标、接口定义**。省了这两步，后面要用三倍时间还 |
| **打样周期不可压缩** | 阶段 3 的 PCB 要尽早启动；用**面包板先验证电路**，避免"画完才发现电路错" |

## 6. 六个常见崩盘点（按概率排序）

| # | 崩盘点 | 后果 | 怎么防 |
|---|---|---|---|
| 1 | 需求没翻译成指标 | 机械做出来装不上/夹不住 | 阶段 0 强制产出《需求-指标表》 |
| 2 | 接口没定义 | 联调时协议对不上、板子装不进 | 阶段 1 强制产出 ICD，且**指定一个负责人** |
| 3 | 电硬进场太晚 | 板子尺寸/路数全错，重画 | 电硬在阶段 1 就出接口清单，PCB 可晚 |
| 4 | 跳过单板验证 | 一次画板就上车，错在哪都不知道 | 面包板验证 + 单板验证，两步都不能省 |
| 5 | 没有方案冻结 | 一直在改，永远在返工 | 设一个明确日期，改走变更流程 |
| 6 | 不演练 7 分钟 | 比赛时手忙脚乱、超时 | 至少跑 3 次完整计时演练 |

## 7. 一句话修正你的模型

> 你原来的理解：**需求 → 硬件 → 代码 → 板子 → 装车**（接力赛）
>
> 修正后：**需求转指标 → 四线并行出接口 → 冻结 → 并行实现 → 集成联调 → 检录验证**
>
> 而且——**电硬从第一步就在场，因为"电"是所有组的公共约束**：
> 机械要知道多重、算法要知道多大功耗、软件要知道什么接口。你不进场，他们就只能猜。
