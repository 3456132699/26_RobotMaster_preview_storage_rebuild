# 开发流程与各组产出物

> 队内文件 · 2026-11-05 · 长庚整理
> 配套：`RoboMini2027_方案设计决策清单.md`（那份讲"要定什么"，这份讲"定完之后怎么干、各自交什么"）
>
> **核心原则**：每个阶段结束时，每个组都必须**交出可以给别人看的东西**。
> 「做完了」不是产出物，「这里有一份东西，你看得懂、能用」才是。

---

## 0. 六个开发单元

| 单元 | 负责范围 | 一句话职责 |
|---|---|---|
| **总体 / 系统集成** | 架构、接口、进度、联调 | 保证各块拼得起来 |
| **机械** | 车体、底盘结构、取物机构、投放机构 | 让东西能动、能抓、能放 |
| **电控硬件** | 主控板、电源、驱动、保护、线束 | 让电安全地变成动作 |
| **电控软件** | 底盘运动、机构时序、状态机、通信 | 让动作按顺序、按节拍发生 |
| **视觉算法** | 目标识别、瞄准解算 | 让机器"看见"靶和物品 |
| **发射机构** ⭐ | 摩擦轮、供弹、云台、瞄准、计弹（独立单元） | 若走弹丸优先，这是第二个机器人 |

> 📌 **发射机构为什么单独拎出来**：它跨机械/电控/软件/视觉四方，有自己的硬性规范（尺寸 <300³、≤16.8 V、失控 0.5 s、堵转 2 s、必须人工急停），还涉及弹丸额度记账。
> 如果走分数优先，这个单元可以暂缺——但**表里保留它的位置**，方便以后加。

## 1. 阶段 0 · 需求 → 指标

**这一阶段唯一的目标**：把「我们要拿分」变成「我们要做到什么数字」。

| 单元 | 产出物 | 具体要求 |
|---|---|---|
| **总体** | 《需求-指标对照表》<br>《目标分数测算》 | 每条功能需求都对应一个可验证数字；目标分算到"要拿几个方块、几次兑换" |
| **机械** | 指标行 + 3 个机构草图 | 夹持力 ≥? N、行程 ≥? mm、动作时间 ≤? s、质量 ≤? kg；**三个方案，不是十个** |
| **电控硬件** | 《电气约束清单》 | 电压上限 16.8 V、电气部分可占重量、板子可用空间、接口需求 |
| **电控软件** | 《控制需求说明》 | 控制频率、需要哪些闭环、状态机有哪些状态 |
| **视觉算法** | 《识别目标定义》 | 要识别什么（靶的"四灯全亮"状态？方块？）、需要多快、多少精度 |
| **发射机构** | 《发射指标》 | 射距包络、初速范围、射速、弹仓容量、命中率目标 |

**这一阶段的三个"不许"**

- 不许直接说「我要做夹爪」——先说是多少牛的夹持力
- 不许用「差不多」「应该够」——写数字，哪怕是估的
- 不许超过 3 个方案——新手做不完十个方案的评估

## 2. 阶段 1 · 方案设计

**目标**：四条线并行推进，靠**接口定义**互相对齐。

| 单元 | 产出物 | 具体要求 |
|---|---|---|
| **总体** | 《系统架构图》<br>《电气接口清单 ICD》<br>《BOM 初稿》 | 架构图要能一眼看出"谁连谁、谁供电给谁"；ICD 是这一阶段最重要的东西（见下方模板） |
| **机械** | 《机构方案说明》<br>3D 初版模型<br>《质量预算表》 | 含构型图、传动比、力矩核算、**安装接口（孔位/孔距/可用平面）**、质量分配 |
| **电控硬件** | 《电源预算表》<br>《接口清单》<br>原理图草图 | 电源预算要**峰值与平均分开算**（电机启动是额定的 3～8 倍） |
| **电控软件** | 《控制架构》<br>《通信协议草案》 | 状态机画出来；协议要有帧格式（帧头/长度/命令/校验/帧尾） |
| **视觉算法** | 《算法方案》<br>硬件选型（相机/算力） | 说明识别思路、需要的算力和功耗（**这直接影响电源树**） |
| **发射机构** | 《发射方案说明》 | 含弹道核算、供弹方案、云台方案、计弹方案 |

### 《电气接口清单 ICD》至少要回答这些问题

- 谁跟谁通信？用什么协议？速率多少？
- 谁给谁供电？几伏几安？峰值多少？
- **地怎么共**？（共地是所有疑难杂症的源头）
- 机械接口：板子多大、几个安装孔、孔距多少、线从哪出？
- 线束长度够吗？会绕到运动部件吗？

> 🔴 **大一队伍最常见的崩盘就在这里**：各做各的，联调时发现协议对不上、板子装不进机构、电源带不动。
> 不是技术不行，是**没人负责把接口写下来**。所以这一阶段必须指定一个 **ICD 负责人**。

## 3. 阶段 2 · 方案冻结

**目标**：宣布「某日之后不再改，除非走变更流程」。**没有冻结 = 所有人都在移动靶上工作。**

| 单元 | 产出物 | 具体要求 |
|---|---|---|
| **总体** | 《冻结版 ICD》<br>《变更流程说明》 | 每一项都有对应组的确认；变更流程要在群里宣布 |
| **机械** | 冻结版 3D 模型<br>《安装孔位图》<br>《外协/打印清单》 | 孔位图要能直接给电控画板、给加工厂下料 |
| **电控硬件** | 冻结版原理图<br>板框尺寸图 | 板框尺寸、安装孔、接口位置都不能再变 |
| **电控软件** | 冻结版协议<br>接口函数定义 | 函数名、参数、返回值要定下来，别人才能对着写 |
| **视觉算法** | 冻结版数据接口 | 输出的数据结构、频率、坐标系 |
| **发射机构** | 冻结版装置尺寸图<br>安装接口图 | 必须 ≤300×300×300 mm，装在 300×300 云台放置台上 |

### 冻结时必须核算的三个合规项

- [ ] **尺寸**：初始 ≤350×350×400 mm（车）、<300³（发射装置）
- [ ] **重量**：≤15 kg（要有合计数字，不是"应该没问题"）
- [ ] **电压**：≤16.8 V

> ⚠️ 这三项**现在不查，后面返工代价极大**——改尺寸要重画板、改重量要换电池、改电压要重选所有器件。

## 4. 阶段 3 · 分头实现

**目标**：各块独立做完、独立验证。**不要等到集成时才发现问题。**

| 单元 | 产出物 | 具体要求 |
|---|---|---|
| **总体** | 周报<br>《风险登记表》 | 每周一次；风险按"会发生/影响多大"排序，不写"暂无风险" |
| **机械** | 加工件实物<br>装配体<br>《干涉检查报告》 | 装配前先做**虚拟装配**，别等实物撞了才发现 |
| **电控硬件** | 《面包板验证记录》→ 原理图 → PCB → 打样 → 焊接 → 《单板上电测试记录》 | **顺序不能跳**：先面包板验证电路，再画板 |
| **电控软件** | 开发板上跑通的功能清单 | 用开发板先跑通逻辑，**不要等板子做出来才写代码** |
| **视觉算法** | 《识别率测试报告》 | 要有数字：识别率 ?%、误识率 ?%、单帧耗时 ? ms |
| **发射机构** | 摩擦轮/供弹/云台单机测试记录 | 分别测：初速稳定性、卡球率、云台重复定位精度 |

### 电硬这一阶段的关键：单板验证不能省

上电顺序固定为：**断电查短路 → 只上电不接负载量电压 → 接 MCU 量复位 → 接外设 → 接电机**。
跳过这一步，板子一上电烧了，你连错在哪都不知道。

## 5. 阶段 4 · 集成与联调

**目标**：从"各块都能跑"变成"整车能跑"。

| 单元 | 产出物 | 具体要求 |
|---|---|---|
| **总体** | 《联调问题清单》<br>每日进度 | 问题分级：致命 / 影响成绩 / 体验问题。**先修致命的** |
| **机械** | 整车装配<br>《拆装手册》 | 手册要写清拆装顺序——现场维修时救命 |
| **电控硬件** | 装车布线<br>《排故记录》<br>抗干扰验证记录 | 布线要满足"整齐不裸露、线束固定"（这是加分项也是检录要求） |
| **电控软件** | 整车状态机<br>《参数表》 | 参数要能快速调（比赛现场要改）；不要散落在代码里 |
| **视觉算法** | 现场调参记录 | 实验室能用 ≠ 现场能用，要记录实际光照/距离下的表现 |
| **发射机构** | 实弹测试数据 | 命中率、初速、卡球率、连续发射稳定性 |

### 联调顺序不能跳

```
单板验证 → 分系统单独跑 → 两两联调 → 整车联调 → 场地实测
```

**联调常见崩溃点**（按概率）：

| 现象 | 根因 |
|---|---|
| 电机一转就复位 | 电源没分路、电容不够、地没处理好 |
| 通信丢包 | 没共地、线太长、电机干扰、波特率不匹配 |
| 机构动了但板子报错 | 电机反电动势灌回、缺续流/隔离 |
| 一切正常但装不进去 | 机械接口没冻结，或板子尺寸后改 |

## 6. 阶段 5 · 验证与上场

**目标**：能通过检录、能在 7 分钟内跑完、坏了能修。

| 单元 | 产出物 | 具体要求 |
|---|---|---|
| **总体** | 《检录自查表》<br>《7 分钟演练记录》<br>《备件清单》 | 演练至少 3 次，记录每次卡在哪、花了多少秒 |
| **机械** | 备件（易损件）<br>现场工具包 | 螺丝、打印件、轴承 |
| **电控硬件** | 检录演示脚本<br>备件板/备件线/保险丝 | 保护动作要能当场演示 |
| **电控软件** | 程序备份（U 盘 ×2）<br>快速重刷流程 | 现场重刷不超过 5 分钟 |
| **视觉算法** | 参数备份<br>降级方案 | 光线不行时的备选参数 |
| **发射机构** | 保护演示：失控断电、堵转断电、急停 | 这三项检录要演示 |

## 7. 三道 Gate（过不了就别往下走）

### Gate 1 · 冻结门（阶段 2 结束时）

- [ ] ICD 每一项都有对应组确认
- [ ] 尺寸 / 重量 / 电压 三项**有具体数字**且合规
- [ ] 决策日志里 A～E 组已填完
- [ ] 板框尺寸、安装孔位已确认并通知机械
- [ ] 变更流程已宣布

### Gate 2 · 联调门（阶段 4 结束时）

- [ ] 整车能**连续跑 3 次**完整流程不崩
- [ ] 没有未解决的**致命**问题（影响成绩的可以有，要列出来）
- [ ] 电机全功率动作时，电源跌落不超过 10%
- [ ] 保护动作全部能演示（失控 0.5 s、堵转 2 s、急停）

### Gate 3 · 上场门（阶段 5 结束时）

- [ ] 检录自查表全过
- [ ] 7 分钟演练至少 3 次，最好成绩达到目标线
- [ ] 备件齐、工具齐、程序备份 ×2
- [ ] 每个上场的操作手都亲手跑过至少 3 次

## 8. 7 分钟时间预算表（把"要快"变成数字）

> **为什么要做这个**：新手队伍最容易犯的错是**假设时间够用**。7 分钟听着不短，但一趟往返、一次对准、一次卡壳都在吃时间。
> 这张表的作用是：**先把时间算出来，再反推机构要多快。**

### 8.1 填这张表（模板）

| 环节 | 单次耗时 | 次数 | 小计（秒） |
|---|---|---|---|
| 驶离启动区 | ? | 1 | ? |
| 往返行驶（启动区 ↔ 高地 ↔ 兑换区） | ? | ? | ? |
| 拾取单个方块（对准 + 夹取） | ? | ? | ? |
| 兑换区对准 | ? | ? | ? |
| 投放（双投） | ? | ? | ? |
| 爬 30° 坡道上二级平台 | ? | ? | ? |
| 取单个能量单元 | ? | ? | ? |
| 打靶（若做发射架，与拾取并行） | ? | — | 可与上面重叠 |
| 卡壳/重试预留 | — | — | ≥60 |
| **合计** | | | **必须 ≤ 420** |

### 8.2 一份参考估算（⚠️ 仅供量级参考，必须实测替换）

按新手队伍水平粗估：

| 项 | 估算 |
|---|---|
| 单趟往返（约 7～8 m，车速 0.7 m/s） | 12～15 s |
| 拾取单个方块 | 3～4 s |
| 兑换区对准（新手） | 8～10 s |
| 双投动作 | 2～3 s |
| **一趟带 3 个方块的循环** | **约 45～50 s** |
| 爬坡上二级平台额外耗时 | +15～20 s |

**推算**：

- 10 个方块，每趟带 3 个 → **4 趟** ≈ 190 s
- 4 个能量单元，分 2 趟带（每趟 2 个才能双投）→ 2 趟 × 66 s ≈ 130 s
- 合计 ≈ **320 s**，理论余量约 100 s

**但这个余量是假的**：
新手实际效率打 6～7 折 → 320 ÷ 0.65 ≈ **490 s > 420 s**

> **所以结论是**：7 分钟**够拿完 10 个方块**（约 200 分基础，双投可到 400 分），
> 但「方块 + 能量单元全拿」对新手**基本不可能**。
> ⇒ 建议把目标定为：**方块全拿 + 视剩余时间取能量单元**，而不是"全都要"。

### 8.3 这张表怎么用

1. 阶段 0 先填一版**估算**（用上表数字起步）
2. 阶段 4 用**实测**替换每一格
3. 如果合计超了 420，不要压缩"预留"，而是**砍动作**（少拿几个 / 放弃某个环节）
4. 阶段 5 演练时用这张表计时，看哪一格超了

## 9. 首次全队会议议程（约 2 小时，可直接用）

| 时长 | 内容 | 产出 |
|---|---|---|
| 5 min | 说明今天要产出什么（不是聊想法，是**拍板 + 分工**） | 会议目标写白板上 |
| 15 min | **A 组：路线与目标**（A1～A4） | 主攻路线 + 目标分数档 |
| 20 min | **B 组：整车构型**（B1～B5） | 底盘形式 + 尺寸策略 + 重量预算 |
| 20 min | **C/D 组：取物与投放** | 夹持方式 + 是否双投 |
| 15 min | **E 组：发射机构**（如做） | 发射方式 + 云台自由度 |
| 15 min | **F/G 组：电源与通信** | 电池规格 + 几块主控 |
| 10 min | **H/I 组：合规与策略** | 加分目标 + 检录负责人 |
| 10 min | **指定产出物责任人** | 每组 1 人 + 交付时间 |
| 5 min | 总结：今天定了什么、谁负责什么 | 决策日志填完 |

**开会三条规矩**

1. **只讨论"选哪个 + 为什么"，不讨论实现细节**（细节留到组内）
2. **有分歧就投票，别追求全票通过**——新手队伍最容易卡在"再想想"
3. **每定一条，当场填决策日志**，指定记录人
4. **卡壳了照 `RoboMini2027_会场救急卡.md` 走**——忘了数据就报保守值+记待查，概念不清就分诊，信息不全就"带条件通过"。不许当场硬撑，也不许无限期推迟

## 10. 新手团队最容易踩的十个坑

| # | 坑 | 后果 | 怎么防 |
|---|---|---|---|
| 1 | 需求不翻译成指标 | 机械做出来装不上/夹不住 | 阶段 0 强制产出《需求-指标表》 |
| 2 | 没有接口定义 | 联调时协议对不上、板子装不进 | 指定 ICD 负责人 |
| 3 | 电硬最后才进场 | 板子尺寸/路数全错，重画 | 电硬阶段 1 就出接口清单 |
| 4 | 没有冻结节点 | 一直在改，永远返工 | Gate 1 |
| 5 | 跳过单板验证 | 一次画板就上车，错在哪都不知道 | 面包板 → 单板 → 整车，三级 |
| 6 | 重量/空间没提前分 | 机械做完了，电池没地方放 | 《质量预算表》 |
| 7 | 不做 7 分钟计时演练 | 比赛时超时、手忙脚乱 | 至少 3 次完整计时 |
| 8 | 决策不留痕 | 散会后各记各的，三周后没人记得为什么 | 决策日志 + 记录人 |
| 9 | 只做"能演示"不做"能比赛" | 实验室演示很漂亮，现场一塌糊涂 | 阶段 4 必须**场地实测** |
| 10 | 没备件 | 坏一个件直接退赛 | 备件清单 |

---

## 11. 一个提醒：别把流程当成负担

上面这套东西看着多，但真正必须坚持的只有**四件事**：

1. **需求写成数字**（阶段 0）
2. **接口写下来**（阶段 1）
3. **有一个冻结日**（阶段 2）
4. **上场地实测**（阶段 4）

其余都是锦上添花。人手不够的时候，**砍流程，不要砍这四条**。
