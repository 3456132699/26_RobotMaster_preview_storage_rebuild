# AI 助手使用公约（每人一个，共用一套事实）

> **队内文件** · 2026-11-05 · 长庚
> 起因：白星提议每人都准备一个长期 AI 助手，全程跟着这个赛事。
> 这份文件说的是：**怎么让六个助手不打架。**

---

## 0. 先给结论：你的判断对八成，缺的那两成是致命的

**你对的部分（我完全同意）**

> 「一个长期的伙伴远比一段一段没有前后、只有知识点问答的对话 AI 更有用。」

对。因为一次性问答只能回答「**是什么**」，长期伙伴能回答「**为什么当初这么定**」。
机器人项目里真正贵的从来不是知识点——是**上下文**：为什么选差速不选麦轮、为什么这个接口这么留、上次那个 bug 最后是怎么好的。这些不在任何教程里。

**缺的那两成**

> AI 继承的是「**你的**上下文」，继承不了「**团队的**事实」。

六个人各自一个 AI，如果不管，会出现：**六个 AI，六套说法**。
你问自己的助手「发射装置能多大」，它说 300³；队友问他的助手，它可能说"没有明确限制"。然后你们在会场上各执一词——**这正是我们花两份文件去防的"假共识"，被 AI 放大成了六份。**

**所以正确的架构不是"每人一个 AI"，是：**

```
共享底座（唯一事实源）  +  个人助手（管自己的活）  +  结论回流（写回文件）
```

三者缺一，这套东西就会变成六个平行宇宙。

---

## 1. 共享底座是哪四件东西

| 文件 | 它回答什么 | 谁维护 |
|---|---|---|
| `RoboMini2027_硬数据速查手册.md` | 规则里的**客观数字**（16.8 V / 15 kg / 300³ …） | 全员可查，改动要通知 |
| `模板与记录/决策日志.md` | **我们定过什么、为什么** | 记录人 |
| `电气接口清单ICD`（阶段 1 起） | **接口长什么样**（几伏几安、协议、孔位） | ICD 负责人 |
| `模板与记录/风险登记表.md` | **哪里可能崩、谁在盯** | 总体 |

> 📌 **这四份是"事实"，AI 的输出是"意见"。冲突时以文件为准，永远如此。**

## 2. 六条公约（贴在心里，不用背）

| # | 公约 | 为什么 |
|:--:|---|---|
| 1 | **AI 说的规则数字，必须能回查到速查手册**，查不到就标"待查"，不许当结论用 | AI 会记错版本、会把相似赛事的规则混进来 |
| 2 | **影响两个组以上的结论，必须写进团队文件**——AI 对话不算记录 | 对话是你的私有记忆，文件才是团队的记忆 |
| 3 | **新对话第一段先贴开场模板**（第 3 节），否则它不知道你是谁、团队定了什么 | 不贴模板 = 每次从零开始，白瞎了"长期" |
| 4 | **别指望 AI"记得"**——长对话到一定长度会丢掉前面的内容 | 重要结论另存文件，这是唯一可靠的记忆 |
| 5 | **不让 AI 替你拍板**：它可以列选项和代价，"选哪个"是人决定的 | 代价由你们承担，不由它承担 |
| 6 | **别贴敏感信息**：账号、密码、他人隐私、家庭住址 | 仓库是私有的，对话不是 |

## 3. 开场模板（新对话第一段，直接复制改）

```
你是我的长期技术助手。以下是固定背景，请在后续对话中一直按它工作。

【我的身份】
- 我在参加 RoboMini 机甲杯 2027：7 分钟对抗赛，1 台拾取车 + 最多 1 个发射架
- 队伍 6 人，都是大一新生，没有机器人比赛经验
- 我负责：<机械 / 电控硬件 / 电控软件 / 视觉算法 / 发射机构 / 总体>

【团队已定的结论】（只贴结论，别贴讨论过程）
- 主攻路线：<>　　目标分数档：<及格 / 目标 / 冲刺>
- 底盘形式：<>　　车体尺寸策略：<>
- 电池：<>　　主控数量：<>
- 其他：

【硬约束，不许改动】（这六条是底线，任何方案都要满足）
电压 ≤16.8 V｜整车 ≤15 kg｜初始尺寸 ≤350×350×400 mm
发射装置 <300×300×300 mm｜失控 0.5 s 内断电｜供弹堵转 2 s 内断电且必须有人工急停

【我的偏好】
- 简体中文，先给结论再给理由，不要客套
- 给方案时列「选项 + 代价」，不要只给一个答案
- 涉及规则数字请注明出处；不确定就直说「不确定」，不要猜
- 我要能动手做的东西：步骤、数值、检查项、判断标准
```

> 💡 **这份模板本身就是"共享底座"的摘要**。它变长了不用怕，**但里面每一个数字都必须和速查手册一致**——不一致就改模板。

## 4. 每次会话开头，补三行状态

模板贴一次就够，但**这三行每次都要更新**（成本 10 秒，回报极大）：

```
本周在做：<一句话>
当前卡在：<一句话，写清具体现象>
最新变更：<队友改了哪个接口/参数；没有就写"无">
```

为什么值得：AI 最常犯的错是**拿两周前的状态给你建议**。你把这三行一贴，它的回答立刻从"泛泛而谈"变成"针对你现在这个坑"。

## 5. 五种最值得问 / 五种别问

**✅ 值得问（它真的比人强）**

| 问法 | 好在哪 |
|---|---|
| 「这是我的电源预算表，帮我逐行核对有没有漏项」 | 有具体对象，它能查错 |
| 「我的现象是 XX，可能原因按概率排序，每条给一个验证方法」 | 排故最需要"可能性排序 + 怎么验" |
| 「把这条规范条款翻译成我要做到的具体数字」 | 规则原文到工程指标的翻译，它很擅长 |
| 「这段代码 / 这张原理图，按 XX 检查清单过一遍」 | 有 checklist 当尺子，输出稳定 |
| 「我下周要交 XX，帮我倒排先后顺序」 | 计划类问题它做得不错 |

**❌ 别问（问了也不会有用）**

| 别问 | 为什么 |
|---|---|
| 「帮我定选哪个方案」 | 它不知道你们的加工能力、人手、恐惧点 |
| 「规则里 XX 是多少」 | 先查速查手册。AI 可能记错版本，这个错误最贵 |
| 「帮我写整份方案」 | 你会失去对方案的掌控，答辩时讲不出来 |
| 「我这个想法好不好」 | 太空泛，只能得到"挺好的，但要注意…" |
| 一次问十个问题 | 回答会全都变浅，不如一个一个来 |

## 6. 每个人自己的知识库（放 `RoboMini2027_<名字>` 对应文件夹）

```
<你的名字>_个人/
├── 我的周报.md        ← 每周抄一份给组里（对应模板 T03）
├── 我的排故记录.md    ← 现象 / 根因 / 改法，一条一条攒
├── 我的学习笔记.md    ← 章节自测结果，错题号记下来
└── 我的问题清单.md    ← 想问但还没问的，攒着一次问清
```

> 白星已有的 `RoboMini2027_电硬/` 就是这个结构的实例，可以直接当模板给组员看。

## 7. 五种常见失败模式（提前知道能省很多时间）

| 症状 | 真正的原因 | 解法 |
|---|---|---|
| AI 答得越来越飘、开始重复 | 上下文太长，早期信息被挤出去了 | 重要结论另存文件，**重开一个对话** |
| 六个人说的不一样 | 各自的 AI 只有各自的理解 | 决策日志是唯一事实源，**每次开工先对齐** |
| 照着 AI 说的做，结果错了 | 没回查，它编了个数字 | 公约第 1 条，参数必须溯源 |
| 问了半小时没结论 | 一次问太多、问题太宽 | 一次一个，带现象 + 已试过的方案 |
| 全队只有一个人在维护文件 | 别人觉得"我 AI 记得就行" | 公约第 2 条：**结论出门要落地** |
